# JB OSINT

Android-приложение для сбора и структурирования открытых данных (OSINT) по одному запросу: e-mail, телефон, домен, IP, никнейм или ФИО. Результат — единый отчёт, который можно выгрузить в PDF, Excel (XLSX), JSON и автономный HTML. Отдельный сценарий — разбор Telegram-канала и выгрузка его аудитории.

В интерфейсе используется единый бренд **«Поиск JB OSINT»**, а в отчёте каждый факт сопровождается именем модуля-источника и ссылкой-доказательством.

## Возможности

- **Единый поиск.** Автоопределение типа запроса (e-mail, телефон, домен, IP, никнейм, ФИО) и параллельный опрос подключённых модулей с таймаутом.
- **Дедупликация и агрегация.** Факты нормализуются (телефоны, домены, e-mail), схлопываются дубликаты, строятся связи «субъект → значение» и матрица совпадений.
- **Оценка достоверности.** Каждый факт получает статус `CONFIRMED` / `PROBABLE` / `UNVERIFIED`, отчёт содержит раздел методологии и ограничений.
- **Свои модули.** Любой сервис с JSON-ответом подключается вручную: название, HTTPS-адрес с маркером `{query}`, способ передачи ключа (Bearer, свой заголовок, параметр адреса, JSON-тело `{"key": …}` или без ключа). Если способ не выбран — приложение само подбирает подключение: пробует GET и POST без тела и передачу ключа через `Authorization: Bearer`, `X-Api-Key` или параметр адреса, выбирая вариант, который вернул 2xx (рабочим считается и 401/403 — адрес и метод верны, ключ отклонён); в карточке на это время горит «Проверяется…», по успеху — «Модуль настроен успешно: GET, bearer». Сразу после сохранения выполняется тестовый запрос: ✅ «Модуль отвечает», ⚠️ «Ошибка 403: Forbidden» и т.п., 🚫 «Нет соединения»; при ошибке модуль автоматически отключается до устранения причины.
- **Быстрая настройка одним ключом.** Достаточно названия, API-ключа и ссылки на сервис (сайт или `@бот`): приложение читает страницу сервиса или описание бота, ищет документацию и само подбирает эндпоинт (`/search`, `/api/v1/search`, …), метод (GET → POST) и способ передачи ключа (`Bearer`, `X-Api-Key`, `?key=`/`?token=`, JSON-тело). Ответ 2xx фиксирует рабочую схему, 401/403 означает «адрес найден, ключ отклонён». Если подбор не удался — «Повторить автонастройку» (продолжает перебор) или «Ручная настройка» с уже подставленным наиболее вероятным шаблоном.
- **Правила разбора (field mapping).** Если ответ сервиса нестандартный, в карточке модуля задаются правила «JSON-путь → поле отчёта» (`data.username`, `data.items[].email`) с необязательной регуляркой для извлечения части значения. Без правил работает автоматический разбор по известным именам полей.
- **Единый формат фактов.** Значения приводятся к каноническим типам (почта, телефон, никнейм/профиль, полное имя, IP, домен, утечка) с нормализацией регистра, телефонов, доменов и URL — поэтому совпадения из разных модулей склеиваются и подтверждают друг друга.
- **Тестировать поиск.** На экране нового исследования есть предпросмотр: список найденных фактов без формирования отчёта и без сохранения в историю; показывает, сколько модулей ответило. Свой модуль работает в поиске наравне со встроенными, у него есть тумблер, проверка ключа и удаление. **В отчёте указывается имя модуля и ссылка на страницу-доказательство**, чтобы каждое сведение можно было проверить.
- **Подробные факты без потери смысла.** Вместе с найденным значением сохраняются соседние поля ответа сервиса (страна, город, провайдер, источник утечки и т.п.): до 8 строк в карточке факта и полный набор в PDF (раздел «Детали исходного ответа»), Excel и JSON.
- **Подключение по одному ключу.** На экране ключей есть поле «Подключение по ключу»: вставьте строку из кабинета сервиса — ключ, ключ вместе с адресом или с названием. Приложение само определит сервис (по префиксу ключа, адресу или названию), сохранит ключ, включит модуль и проверит его; для незнакомого адреса соберёт свой модуль и подберёт способ передачи ключа. Ход и итог видны в диалоге по шагам.
- **Починка модулей.** В отчёте диагностики кнопка «Починить» разбирает коды ответов: 404/405/401/403/415/422 — заново подбирает адрес и способ передачи ключа, адрес встроенного сервиса — предлагает перенести ключ во встроенный модуль, 429 — просит повторить позже, VK — подсказывает про пользовательский токен Implicit Flow. Каждое действие пишется в журнал починки, после него диагностика повторяется.
- **Диагностика модулей.** Кнопка «Диагностика» на экране ключей опрашивает все включённые модули и собирает отчёт: запрос (секреты замаскированы `***`), HTTP-код, время ответа, размер, структура JSON (пути к объектам и массивам), число разобранных фактов, поля правил, образец ответа и оценка («работает» / «0 фактов — задайте правила» / «код 403»). Отчёт копируется в буфер одной кнопкой и передаётся разработчику; секреты (ключи, токены, JWT, `Bearer`) вырезаются из любых полей, включая тексты ошибок сервисов.
- **Интеллектуальный ассистент (любой поставщик).** Отдельная вкладка «Интеллектуальный ассистент» в настройках: выбор поставщика — Hugging Face, OpenRouter, OpenAI, Groq, DeepSeek, Mistral или **свой OpenAI-совместимый сервер** (нужен только базовый `https://…/v1`). У каждого поставщика свой ключ и своя модель, ключи хранятся раздельно. Проверка ключа — через `whoami` (Hugging Face) или список моделей `GET /models`; затем пять сценариев.
  - **Аналитик** — связывает цифровые следы в связную картину, отделяет установленные факты от предположений.
  - **Исследователь** — сам формулирует 2–4 поисковых запроса, ищет их в публичной выдаче DuckDuckGo и делает выжимку найденного; в ответе перечислены ссылки на найденные страницы.
  - **Классификатор** — определяет тип значения (почта, телефон, никнейм, домен, IP, имя…) и релевантность; результат показывается меткой «ИИ: тип · релевантность» в карточке факта.
  - **Планировщик запросов** — до запуска модулей уточняет формулировку запроса.
  - **Синтезатор отчёта** — оформляет аналитическое резюме с заголовками и выводами; резюме попадает в PDF, Excel и JSON.
  - Сценарии включаются тумблерами и могут выполняться автоматически после поиска (типы, анализ, веб-исследование, резюме); всё можно запустить вручную кнопками на экране результатов.
  - Модели: у Hugging Face — `openai/gpt-oss-20b` (по умолчанию), `openai/gpt-oss-120b`, `meta-llama/Llama-3.1-8B-Instruct`, `meta-llama/Llama-3.3-70B-Instruct`, `Qwen/Qwen3.5-9B`, `deepseek-ai/DeepSeek-V3`; у остальных поставщиков — их ходовые модели; любой другой ID можно ввести вручную.
  - Запросы идут напрямую на `https://<базовый адрес>/chat/completions` (HTTPS, Bearer-токен), ключ ассистента хранится в отдельном зашифрованном хранилище. При редиректе на другой хост запрос прерывается, чтобы ключ не ушёл третьей стороне.
- **ИИ-ассистент модулей.** На экране ключей кнопка «ИИ-разбор»: приложение опрашивает включённые модули, само разбирает коды ответов и структуру JSON, берёт готовые рекомендации из кэша по отпечатку проблемы и только нестандартные случаи отправляет модели — одной пачкой до пяти модулей, с коротким JSON-промтом. Видны счётчики запросов, попаданий в кэш, потраченных и сэкономленных токенов, журнал обращений к ИИ и выгрузка отчёта в JSON, Excel, PDF и HTML. Без ключа ассистента остаются локальные рекомендации.
- **Резервные копии и режим работы.** Экспорт/импорт всех ключей в зашифрованный `jb_osint_keys.json` (PBKDF2 → AES-256-GCM), автовосстановление после переустановки, режимы «Администратор»/«Пользователь» с мастер-паролем, блокировкой после пяти ошибок, резервным кодом и входом по биометрии, а также «пользовательская сборка» `jb_osint_config.bin` для передачи приложения вместе с настройками.
- **Управление API-ключами.** 25 источников, сгруппированных по темам; у каждого — тумблер включения, подсказка по формату ключа, ссылка на страницу выдачи и кнопка проверки валидности.
- **Шифрование ключей.** Ключи хранятся в `EncryptedSharedPreferences` (Android Keystore, AES-256-GCM), в UI показываются только маской.
- **Отчёт-досье.** Документ собирается как полное досье: введение, методология, сводные данные о субъекте, разделы по типам следов, доказательная база, документы и медиа, аналитическое заключение, оценка достоверности, ограничения и приложения.
  - PDF — 20+ страниц: титул; **0. Введение** (объект, основание и цели, использованные источники, структура документа); **0.1 Методология**; **1. Сводные данные** (профиль субъекта с колонкой «Источник подтверждения», показатели сессии, распределение по категориям); **2.1 Telegram-профили**, **2.2 Социальные сети**, **2.3 Электронная почта**, **2.4 Утечки данных**, **2.5 Связи и пересечения**, **2.6 Доказательная база** (блоки «значение → источник → ссылка → дата → статус → примечание»); **3. Документы**, **4. Медиа**; **5.1 Аналитическое заключение**, **5.2 Оценка достоверности**, **5.3 Ограничения**; приложения A (словарь), B (**источники и ссылки**), C (сведения о документе). Колонтитулы, шрифт Inter встроен в APK.
  - HTML — автономный файл со встроенными стилями: сводка, разделы по категориям, поиск по лицу, источники и ссылки-доказательства; открывается в любом браузере без интернета.
  - XLSX — 12 листов: «Сводка», «Доказательства» (значение, источник, ссылка, дата, статус, примечание), «Реестр» (с колонками «Источник» и «Ссылка»), «Люди», «Контакты», «Технические», «Документы», «Медиа», «Источники» (модули и собранные ссылки), «Связи», «ИИ-заключение», «Методология»; стили, закреплённые заголовки, автофильтр.
  - JSON — схема `jb-osint/report/2.0`: `query_type`, `photo_note`, `sections` (telegram / social / emails / leaks / documents / media), `sources`, у каждого факта `first_seen`, `source_names`, `evidence_url`, `status`, `note`, `urls`; блок `ai_analysis` (`analysis`, `narrative`, `notes`).
- **Доказательная база.** Каждый факт несёт имя модуля-источника и прямую ссылку на страницу-доказательство (профиль GitHub, запись HIBP, отчёт VirusTotal, карточка IP, объявление и т.п.). Ссылки собираются из ответа модуля и дублируются в PDF (2.6 и приложение B), XLSX (листы «Доказательства» и «Источники») и JSON (`evidence_url`, `urls`).
- **Поиск по фотографии.** Кнопка «Поиск по фотографии» на главном экране: приложение читает файл, считает SHA-256 и перцептивный хэш, разбирает EXIF (устройство, дата съёмки, геометка, автор/права), находит лица на снимке (ML Kit, модель встроена в APK), затем выполняет обратный поиск по изображению через SauceNAO (нужен бесплатный `api_key` в списке источников). Найденные ссылки попадают в доказательную базу, а профили (X/Twitter, VK, Instagram, GitHub, Telegram) автоматически проверяются обычным поиском. Карточка снимка и примечание о методике выводятся на экране результатов и в отчётах; при отсутствии ключа приложение честно указывает, что внешний поиск не выполнялся, и ограничивается техническими данными файла.
- **Сохранение и отправка.** Файлы публикуются в общую папку `Documents/JB_OSINT_Reports` (Android 10+) либо во внешнее хранилище (Android 8–9) и открываются через системный Share Sheet.
- **Приватность.** `FLAG_SECURE` (скриншоты и превью в списке задач скрыты), HTTPS-only (`usesCleartextTraffic=false`), отключён автобэкап, история поиска хранится в зашифрованном виде с автоочисткой (7/30/90 дней или вручную).
- **Тёмная тема** с акцентами `#4F5BFF` / `#8B5CF6`, фон `#0B0E14`, шрифт Inter (Regular / SemiBold / Bold).

## Автономные AI-агенты, TRONK.PRO и поиск по фото

Раздел «Агент» в нижнем меню — автономный режим с четырьмя вкладками.

### Агент

- **Каскад по стоимости.** Агент сам определяет тип запроса (ФИО, телефон, email, ник, домен, VIN) и раскладывает модули по ступеням: бесплатные (DuckDuckGo, Wikipedia, GitHub, GitLab, RDAP, urlscan) → по ключу (TGStat, VK, Hunter, OpenCorporates, Яндекс, Brave, Google) → платные (Dyxless, LeakCheck, HIBP, VirusTotal, Shodan, SerpAPI, TeleSINT, TRONK).
- **Экономия токенов.** Платных шагов не больше трёх за прогон; если открытые источники дали 40+ фактов, платные шаги пропускаются с пометкой «Пропущено: открытые источники дали достаточно данных». В отчёте указано, сколько платных запросов выполнено, и есть отдельная пометка «Данные собраны без использования платных API».
- **Без токенов приложение работает полностью:** бесплатные модули не требуют ключей, остальные блоки показывают «нет данных», а не выдуманные значения.
- **Анонимизация источников.** В отчёте каждый модуль — «Модуль N». Реальные названия и ссылки собраны в блоке «Приложение B» в приложении; в PDF/Excel/JSON они попадают только в раздел источников.
- **Утвердительная форма.** Факты формулируются как утверждения («У объекта «X» зафиксирован телефон: …»), статус достоверности (Подтверждено / Вероятно / Требует проверки) выводится отдельным полем. Аналитические предположения вынесены в отдельный блок с указанием основания.
- **Результат** можно открыть как профиль объекта или выгрузить в PDF/Excel/JSON.

### Авто (TRONK.PRO)

- Вход: VIN, номер кузова или госномер.
- Локально (без ключа): разбор VIN — WMI и регион сборки, год выпуска, проверка контрольной суммы; плюс ссылки на ГИБДД, реестр залогов, Autoteka, Авито, Дром, Авто.ру.
- С ключом TRONK: ДТП, залоги, пробег, число владельцев, ремонты, средняя цена, фото объявлений, парковочные сессии. Разбор ответа терпимый — поддерживаются разные имена полей контракта.
- Отчёт: сводка, утверждения со статусами, предположения (например, «возможен скрученный пробег»), ссылки для ручной проверки.

### Поиск по фото

- Локально: SHA-256, перцептивный dHash, размеры, EXIF (устройство, дата, геометка, автор), число лиц.
- Автоматически: SauceNAO (бесплатный ключ) и любой сервис поиска по лицу (адрес задаётся в ключах).
- Совпадения дедуплицируются по нормализованному адресу (без UTM, якорей, мобильных доменов), получают платформу (VK, ОК, Instagram, Facebook, X, TikTok, YouTube, Telegram, Discord, Reddit, 2ch, Авито, Mamba, Badoo, Tinder и др.), схожесть и статус достоверности.
- Из адресов извлекаются никнеймы — кнопка «Добавить в досье» передаёт совпадения и ники в профиль объекта.
- Сервисы без публичного API (Яндекс.Картинки, Google Lens, Bing Visual Search, TinEye, IQDB, поиск по аватару в Telegram) даны ссылками для ручной проверки — это честно помечено, а не выдаётся за найденное совпадение.

### Маршрутизация и устойчивость

- **Открытые источники запускаются всегда.** Если ни один модуль не настроен, поиск больше не возвращает пустоту: автоматически идут DuckDuckGo, Wikipedia, GitLab и urlscan. В плане агента это видно как шаг «Открытые источники (ключи не заданы)».
- **Тип запроса можно задать вручную.** В карточке агента есть переключатель: Авто / ФИО / Телефон / Email / Ник / VIN / Домен. Авто-режим определяет тип по виду запроса, ручной — принудительно строит цепочку под нужный тип.
- **Проверка Telegram-ника до запроса.** Username: латиница, цифры и подчёркивание, 5–32 символа, начинается с буквы; числовой ID принимается отдельно. Неверный ввод отсекается с понятной причиной, платные модули не тратятся.
- **Журнал модулей.** Каждый вызов коннектора пишется в журнал: модуль, запрос, сколько фактов, время, ошибка. В карточке агента блок «Журнал модулей» показывает, кто ответил, кто упал и почему «данных нет».
- **TRONK.PRO: базовый URL задаёт пользователь.** Адрес API зависит от тарифа, зашитый хост может быть недоступен; без URL модуль честно сообщает об этом, а не молчит.
- **Повторные попытки и паузы.** Сетевой слой повторяет запросы при 429/5xx с нарастающей паузой, страницы читаются с таймаутом и лимитом размера.

### Глубина поиска

- **Многошаговый проход.** После первого круга из найденного выбираются точные зацепки (почта, телефон, ник, домен), по ним запускается следующий проход — до трёх. Глубина переключается в карточке агента: 1 проход / 2 прохода / глубоко. Платные модули вызываются только на первом проходе, чтобы углубление не умножалось на счёт.
- **Чтение страниц.** Ссылки из выдачи не остаются ссылками: страница скачивается (HTTPS, лимит 400 КБ), из HTML вынимаются заголовок, описание, текст, почты, телефоны, никнеймы и название организации. Соцсети и файлы не читаются — для них есть отдельные модули.
- **Расшифровка VIN через NHTSA vPIC.** Открытый API без ключа: марка, модель, год, страна и завод сборки, кузов, двигатель. Работает вместе с локальным разбором VIN и TRONK.
- **Соцсети глубже карточки:** посты ВКонтакте (wall.search), упоминания в коде GitHub (search/code), посты каналов через TGStat, Reddit (публичный JSON, без ключа).
- **Склейка сущностей.** Телефоны в `+7…`, почты в нижнем регистре, ники без `@` и из ссылок, имена с транслитерацией — «Юлия» и «Yulia» считаются одним человеком, дубликаты в графе не плодятся.
- **Фото по ссылке.** Google Lens и Bing Visual Search через SerpAPI для публичного адреса изображения (аватар из профиля, картинка из объявления) — без загрузки файла на сторонний сервис.

### Шаблоны отчёта

В карточке отчёта агента — четыре шаблона: «Быстрый чек» (одна страница: объект, ключевые факты, риски), «Глубокое досье» (все факты, предположения, план сбора, приложение B), «Анализ авто» (раздел про автомобиль + чек-лист перед сделкой), «Анализ бизнеса» (организации, домены, почты, репутация). Каждый выгружается в HTML и открывается через «Поделиться».

### Анализ продавца

На вкладке «Авто» есть поле «Телефон продавца»: номер уходит в общий каскад (утечки, Telegram, оператор, корпоративные адреса), результат — факты со статусами и номерами модулей.

### Связка «фото → агент»

Если по фотографии нашлись никнеймы, кнопка «Передать @ник агенту» подставляет его в запрос и запускает каскад — так совпадения по фото превращаются в полноценный поиск по человеку.

### Мониторинг объявлений

Критерий (марка/модель/объект, максимальная цена) сохраняется в зашифрованном виде. Кнопка «Проверить» опрашивает открытый веб-индекс и показывает новые ссылки относительно предыдущего прогона; при находках приходит локальное уведомление (разрешение запрашивается на вкладке). Фоновая работа без открытого приложения не выполняется — службы и планировщика нет.

## Профиль пользователя (единый центр результатов)

Экран «Профиль объекта» собирает данные всех модулей в одну карточку: обычный поиск (факты), Telegram-парсер (канал и участники), TeleSINT (карточки, история имён, связи) и импортированная выгрузка сообщений.

- **Карточка объекта** — аватар-инициалы, имя, `@ник`, ID, ссылка на профиль, статус (Активен / Заблокирован / Удалён) и полнота профиля в процентах.
- **Сводка** — сообщения, медиа, контакты, период активности, география, оценка; доли типов контента (текст, медиа, реплаи, кружки, голосовые, ссылки).
- **Идентификаторы** — ники, ID, телефоны, email, домены с указанием платформы, достоверности и ссылкой-доказательством; история смены имён с датами.
- **Круг общения** — граф связей (Canvas, без сторонних библиотек), список тех, кому объект отвечает, частота общения и последняя активность.
- **Поведенческий анализ** — тепловая карта 7×24, пик активности, доля ночных сообщений, средние и максимальные паузы, тональность по словарю, темы обсуждений.
- **Контент-анализ** — облако слов, разбор ссылок по доменам, медиа по типам, EXIF-метаданные (если модуль их вернул).
- **Внешние связи** — найденные профили в других соцсетях и готовые ссылки для ручной проверки ника (без фоновых запросов к площадкам).
- **Репутационный скоринг** — индексы токсичности, спама и доверия с расшифровкой.
- **Медиа и сообщения** — фильтры по типам, порционная подгрузка (по 60/100), выгрузка сообщений и круга общения.
- **Инструменты** — Excel (5 листов), CSV сообщений, CSV аудитории, GraphML для Gephi, HTML-досье по трём шаблонам, сравнение двух профилей, ИИ-досье через ассистента, PIN на раздел анализа, очистка кэша.
- **Алерты** — сравнение с предыдущим сохранённым профилем: смена ника, новые группы, новые контакты, рост токсичности.

Если модуль ничего не вернул, блок показывает «Данные по этому параметру не найдены» — значения не додумываются. Профили кэшируются в зашифрованном виде (AES-256/GCM, ключ в Android Keystore) и открываются оффлайн.

### Выгрузка сообщений

Анализ переписки включается импортом: «Профиль → Загрузить выгрузку». Подходят CSV из Telegram Desktop (колонки «Дата», «Время», «Отправитель», «Текст»; разделитель `;` или `,`) и JSON-массив `[{date|at, author|from, text, type, reply_to}]`. Демо-набор — кнопка «Демо-профиль» на пустом экране профиля.

## Сборка

Требования: JDK 17, Android SDK (platform 35, build-tools 35.x), Gradle 8.11+.

```bash
export ANDROID_HOME=/path/to/android-sdk
echo "sdk.dir=$ANDROID_HOME" > local.properties

./gradlew :app:assembleDebug        # debug APK (ARM + x86 для эмулятора: -PjbAllAbis=true)
./gradlew :app:assembleRelease      # release APK (R8 + shrink)
./gradlew test                      # unit-тесты (report-core + app)
./gradlew :app:lintDebug            # lint; ошибки останавливают сборку
```

**Подпись.** Ключ и его пароли в репозитории не хранятся, пароля по умолчанию нет. Значения берутся
только из `keystore.properties` в корне (образец — `keystore.properties.example`, файл в `.gitignore`)
или из переменных окружения `JB_KEYSTORE_FILE`, `JB_KEYSTORE_PASSWORD`, `JB_KEY_ALIAS`,
`JB_KEY_PASSWORD`. Если ключ или пароль не заданы, `assembleRelease` собирает неподписанный APK,
а не падает с ошибкой.

**Размер APK.** Нативные библиотеки ML Kit (распознавание лиц) занимают ~33 МБ из 39 МБ, потому что
лежат под четыре ABI. По умолчанию в сборку попадают только `armeabi-v7a` и `arm64-v8a`;
для запуска на эмуляторе добавьте `-PjbAllAbis=true` (вернёт x86/x86_64, APK вырастет примерно вдвое).

**CI.** `.github/workflows/ci.yml` собирает и тестирует проект на каждый push, прогоняет lint
и публикует debug APK. Release собирается только при заданных секретах `JB_KEYSTORE_BASE64`,
`JB_KEYSTORE_PASSWORD`, `JB_KEY_ALIAS`, `JB_KEY_PASSWORD`.

## Источники (модули)

Дополнительно можно добавить собственные модули (см. выше) — количество не ограничено, каждый хранится в зашифрованном виде.

Поиск: Google CSE (ключ + CX), Яндекс XML (ключ + folderid), Brave Search, SerpAPI, DuckDuckGo и Wikipedia — последние два без ключа.

Инфраструктура: VirusTotal, Shodan, urlscan.io (без ключа), SecurityTrails (поддомены), IPinfo, RDAP (без ключа). Почта и телефоны: Hunter, Numverify, AbuseIPDB (репутация IP), Have I Been Pwned (утечки). Соцсети: GitHub, GitLab (без ключа), VK, Telegram через TGStat. Реестры: OpenCorporates. Плюс демо-модуль для проверки интерфейса без ключей.

**LeakCheck (ключ 32 символа).** Участие адреса, телефона, ника или домена в утечках через публичный API `leakcheck.io/api/public`: модуль показывает, в скольких записях значение встречается, какие это наборы данных и какие типы полей. Пароли и сами записи не забираются и в отчёт не попадают — только названия утечек, даты и состав данных. Запросы ограничены по частоте самим сервисом, поэтому при ответе 429 модуль просто пропускается.
**Dyxless (платный, ключ проекта v3).** Ключ вида `dyx3_…` приложение узнаёт по префиксу и подключает само; рядом указывается лимит расхода в рублях (по умолчанию 10 ₽). Поиск асинхронный — создание `/v3/searches`, ожидание статуса с учётом `Retry-After` и чтение `/v3/searches/{id}/results`; поддерживаются email, телефон, IP, ФИО из трёх слов, Telegram по нику (`@ник`) и по ID (`id:123456789`). Пустой результат не оплачивается, при `failed` резерв возвращается на баланс. Telegram-поиск стоит 10 ₽, поэтому для него лимит должен быть не меньше 10.
**TeleSINT (Api-Key, 32 символа, платно).** Прямой доступ к базе Telegram: карточка пользователя (история имён, членства, premium, последняя активность), похожие пользователи, карточка канала/чата, похожие каналы, поиск по нику, телефону или имени и постраничная выгрузка участников группы (до 1000 на страницу). База — `https://api.telesint.dev/v1`, авторизация заголовком `Api-Key`; цены запросов 1–15 ₽, повторный доступ к участникам того же канала в течение часа бесплатен. Проверка ключа идёт через бесплатный `/v1/me/` и показывает баланс. Ошибки разбираются по кодам: 401 — неверный ключ, 400 — недостаточно средств, 404 — объект не найден, 429/503 — лимиты. В обычном поиске модуль срабатывает только для ника, телефона или имени и только при сохранённом ключе.

**Поиск по лицу (ProFaceFinder, ключ + адрес API).** Отдельный модуль для фотографий: к ключу добавляется второе поле «URL API (https)» — публичной документации у сервиса нет, поэтому адрес эндпоинта задаётся вручную. Снимок уходит multipart-запросом, ответ разбирается терпимо (`url`/`link`/`page_url`, `similarity`/`score`/`confidence`, вложенные конверты `results`/`matches`/`data`). Совпадения ниже 50% отбрасываются, в отчёте каждому присваивается статус по порогам: ≥90% при подтверждении тем же ресурсом из другого модуля — «Подтверждено», 60–89% — «Требует проверки», ниже — «Не подтверждено». Совпадение изображения не считается доказательством тождества личности — в PDF это сказано прямо.
Модули без ключа включаются тумблером и проверяются кнопкой «Проверить» — ключ для них не запрашивается. Для остальных ссылка «Где взять ключ» ведёт на актуальную страницу выдачи токена.

## Telegram-парсер

Отдельная вкладка «Telegram» (тип анализа, не часть обычного поиска — каждый запрос платный):

1. Укажите канал (`@name` или ссылку `t.me/name`) и число страниц участников (по 1000 на страницу; приложение тянет по 200 за запрос).
2. «Собрать аудиторию» — модуль загружает карточку канала (название, подписчики, описание, ссылка), затем страницы участников; прогресс виден на кнопке, лимиты TeleSINT соблюдаются.
3. Результат: карточка канала и список аудитории (ник, имя, телефон, premium, бот, последняя активность) — первые 50 строк на экране.
4. Выгрузка: **HTML-отчёт** (сводка, профиль канала, таблица аудитории, источники), **CSV** (BOM + `;` — открывается в Excel без настроек) и **Excel** (общий формат отчёта). Файлы сохраняются в `Documents/JB_OSINT_Reports` и открываются через «Поделиться».

Если ключ TeleSINT не задан или канал не найден, экран показывает понятную причину; частичная выгрузка помечается прямо в отчёте.

## Интеллектуальный ассистент

Ассистент — необязательный слой поверх поиска: он не ходит в платные источники и не подменяет факты, а работает с уже собранными данными.

1. Настройки → «Интеллектуальный ассистент» → вставьте ключ Hugging Face (страница выдачи открывается по ссылке из приложения) → «Сохранить».
2. «Проверить» обращается к `https://huggingface.co/api/whoami-v2`: код 200 — ключ активен, 401/403 — отклонён, нет сети — «Нет связи».
3. Выберите модель или введите ID вручную и включите нужные сценарии.
4. На экране результатов доступны кнопки «Проанализировать», «Интернет-поиск», «Оформить резюме»; выводы сохраняются в истории и попадают в отчёты.

Ошибки сервиса переводятся в понятный текст: «Hugging Face не принял ключ (код 401)», «Модель не найдена — проверьте ID», «Слишком много запросов, попробуйте позже». Если ключ не задан, ассистент молчит и поиск работает как обычно.

Помимо OpenAI-совместимых поставщиков поддерживается **Perplexity Agent API** (`https://api.perplexity.ai/v1/agent`, ключ `pplx-…`): запрос идёт с инструментом `web_search`, структурированной схемой ответа и уровнем усилий low/medium/high (селектор в настройках). Ответы кэшируются на сутки по запросу и модели, поэтому повторный разбор того же дела не тратит лимит. Если сервис не принимает поле `effort`, клиент автоматически повторяет запрос с полем `preset`; при отказе ключа или сети включается прежний путь через DuckDuckGo и локальную выжимку.

### ИИ-ассистент модулей (экономия токенов)

Экран «Ключи» → кнопка **«ИИ-разбор»**. Ассистент проверяет включённые модули и объясняет, что именно сломалось, тратя минимум токенов:

1. **Локальный анализ — без модели.** Код ответа, состояние ключа, структура JSON (`JsonShape`), число разобранных фактов и заданные правила разбираются на телефоне. Классы проблем: ключ не задан / отклонён, нет связи, 429, 401–403, 404–405, прочие 4xx, 5xx, «не JSON», «0 фактов», «поля не распознаны». Для каждого класса есть готовый совет: перевыпустить ключ, нажать «Починить», задать правила полей и т. п.
2. **Кэш рекомендаций.** Отпечаток проблемы — SHA-256 от типа проблемы, класса кода, формы JSON (числа из структуры выбрасываются) и правил разбора. Совпал отпечаток — ответ берётся из кэша и запрос к модели не выполняется. Срок жизни записи — 30 дней, файл `module_assistant.json` во внутренней папке приложения.
3. **Пакетная отправка.** В модель уходят только те случаи, где правило бессильно: нестандартное тело ответа, нераспознанные поля своего модуля, отклонённые параметры запроса. Модули объединяются в пачки до пяти, промт — компактный JSON состояния с маской секретов, ответ — строгий JSON-массив с причиной, шагами и предложенными правилами `путь → поле`.
4. **Журнал и статистика.** Каждое обращение к ИИ пишется в журнал: время, поставщик и модель, модули, объём промта и ответа, оценка токенов, ошибка. На экране видны счётчики «запросов к ИИ / из кэша / локально», «токенов потрачено / сэкономлено» и доля экономии.
5. **Отчёт.** Состояние модулей, рекомендации и статистика выгружаются в **JSON** (`jb-osint/modules/1.0`), **Excel** (листы «Модули» и «Сводка»), **PDF** (титул, сводка, карточки модулей с шагами) и **HTML**. Ключи и токены в отчёт не попадают: значения заменяются на `***`, адреса показываются без параметров авторизации.

Если ключ ассистента не задан, разбор всё равно работает — остаются локальные рекомендации и пометка, что ИИ не подключён. Оценка токенов приблизительная (3 символа ≈ 1 токен) и служит для сравнения прогонов, а не для сверки со счётом поставщика.

## Резервные копии ключей и режим работы

Ключи живут только на устройстве, поэтому при удалении приложения они пропадают. Раздел
«Настройки → Резервное копирование» закрывает эту проблему:

1. **Экспорт.** «Экспортировать ключи» собирает ключи встроенных модулей, ключи ассистента и свои модули с их ключами, спрашивает мастер-пароль, шифрует всё им и сохраняет `jb_osint_keys.json` в `Documents/JB_OSINT_Reports` (плюс копия во внутренней папке приложения, FileProvider для «Поделиться»).
2. **Импорт.** «Импортировать ключи» открывает системный выбор файла, спрашивает пароль и восстанавливает ключи: включённые модули, вторые поля (например, логин Hunter), поставщик и модель ассистента, свои модули с правилами разбора.
3. **Автовосстановление.** При запуске, если ключей нет, а рядом лежит копия, приложение показывает диалог «Обнаружена резервная копия ключей. Восстановить?» и просит пароль. Копия во внутренней папке переживает обновление версии.

Шифрование: PBKDF2-HMAC-SHA256 (210 000 итераций, случайная соль 16 байт) → ключ AES-256,
далее AES/GCM с случайным IV и проверкой целостности. Конверт — JSON с параметрами KDF и шифра;
неверный пароль или изменённый файл дают понятную ошибку, а не мусор. Мастер-пароль нигде не хранится: в зашифрованном виде лежит только его PBKDF2-хеш.
Проверено unit-тестами: roundtrip, отказ при неверном пароле, отказ при подмене байта, разные
соль/IV у одинаковых данных, разбор формата без пароля.

**Режим работы** (там же, «Настройки → Режим работы»):

- **Администратор** — полный доступ: ключи, модули, настройки, резервные копии.
- **Пользователь** — нижнее меню сжимается до поиска, экраны ключей, настроек и ИИ-разбора закрыты, попытка открыть их даёт понятное сообщение. На экране видна плашка «Режим пользователя» с кнопкой входа.
- Переключение в «Администратора» и вход в «Ключи» или «Настройки» требуют мастер-пароль (минимум 8 символов; в зашифрованном хранилище лежит только PBKDF2-хеш с солью). Пять неверных вводов блокируют вход на 5 минут с обратным отсчётом.
- **Резервный код** (`XXXX-XXXX-XXXX-XXXX`, показывается один раз) сбрасывает забытый пароль.
- **Биометрия.** На устройствах с BiometricPrompt вход администратора можно разблокировать отпечатком или лицом; шаблон остаётся в системе и приложению не передаётся.

**Пользовательская сборка.** «Создать пользовательскую сборку» сохраняет `jb_osint_config.bin`:
только включённые модули, их ключи (в зашифрованном виде) и настройки. Получатель ставит APK,
кладёт файл рядом и вводит пароль сборки — приложение применяет конфигурацию и переходит в режим
«Пользователь». Если файла нет, приложение остаётся в режиме «Администратор».

## Безопасность

- Ключи и история — только в зашифрованном хранилище; открытый текст в логах не появляется.
- PIN на раздел анализа хранится как PBKDF2-HMAC-SHA256 с индивидуальной солью (120 000 итераций),
  а не как голый SHA-256; после пяти ошибок ввод блокируется на 30 с с удвоением паузы. Старые
  PIN-коды в формате SHA-256 по-прежнему принимаются и автоматически переводятся в новый формат
  после первого удачного ввода.
- Сетевые запросы идут по HTTPS, сертификаты проверяются системным trust store; ключи передаются в заголовках/параметрах и не логируются.
- Экспортированные файлы создаются в приватном кэше и передаются получателю через `FileProvider` с временным grant.
- В отчётах нет названий источников — только «Поиск JB OSINT».

## Ограничения

- Модули, требующие платных ключей, без ключа пропускаются; демо-режим возвращает синтетические данные для проверки интерфейса и экспорта.
- Приложение не обходит авторизацию, капчи и закрытые разделы: собираются только открытые данные, доступные по официальным API.

## Подпись

Release APK подписывается ключом из `keystore.properties` или переменных окружения (см. раздел «Сборка»).
Сам ключ и его пароли в репозитории не хранятся: без них APK остаётся неподписанным и его нужно
подписать вручную через `apksigner`. Отпечаток сертификата фиксируется в описании каждого релиза —
сверяйте его при установке обновления поверх предыдущей версии.

## Вкладка «Утечки» и архитектура источников

### Проверка утечек

Отдельная вкладка **«Утечки»** принимает email или телефон и опрашивает только официальные API
проверки утечек: **Have I Been Pwned** (`hibp`) и **LeakCheck** (`leakcheck`). Результат — список
фактов «сервис / набор данных / дата / типы скомпрометированных полей» со ссылкой-доказательством и
уровнем достоверности.

Политика вкладки:

- пароль **не вводится и не хранится** — ни в открытом виде, ни в виде хеша;
- запрашиваются только метаданные утечки, а не сами записи;
- используются только официальные API, без скрейпинга закрытых страниц и без баз, полученных
  неправомерным путём;
- проверять следует свои данные или данные с согласия владельца (152-ФЗ).

Ключи задаются в разделе **«Ключи»**: `hibp` и `leakcheck`. Без ключей вкладка честно сообщает,
что проверка невозможна, а не выдумывает результат.

### Контракт `IDataSource`

Все источники реализуют единый интерфейс (`data/source/IDataSource.kt`):

```kotlin
interface IDataSource {
    val info: SourceInfo
    fun supports(type: SourceType): Boolean
    suspend fun search(params: SearchParams, key: KeySource): List<RawFact>
}
```

- `SourceType` — смысловой тип (`PERSON`, `CONTACT`, `TRANSPORT`, `SOCIAL`, `DOCUMENT`, `LEAK`,
  `REALTY`, `COMPANY`, `TECHNICAL`).
- `SearchParams` — запрос; `kind` определяется автоматически (`QueryDetector`).
- `SourceInfo` — id, название, типы, описание, признаки `keyless` и `officialApi`.
- `ConnectorDataSource` — адаптер, превращающий существующий `Connector` в `IDataSource` без
  переписывания модуля.
- `DataSourceRegistry` — декларативный реестр, из которого экраны берут источники по типу
  (`DataSourceRegistry.leakSources`, `supports(SourceType.LEAK)`).

### Как добавить новый источник

1. Реализуйте `Connector` (метод `collect(query, key): List<RawFact>`) в `data/Search.kt` или
   отдельном файле и зарегистрируйте его в `Connectors.all`.
2. Добавьте ключ и подсказку в `ProviderCatalog` (`data/Keys.kt`), если сервису нужен API-ключ.
3. Опишите источник одной строкой в `DataSourceRegistry.definitions`
   (`id`, `title`, `types`, `description`).
4. Для нового смыслового типа расширьте `SourceType` — экран и агент подхватят его автоматически.

Внешние REST-сервисы с JSON-ответом можно не кодировать: они подключаются вручную на экране
«Ключи» (адрес с маркером `{query}`, способ передачи ключа, правила JSON-путей).

### Структура отчёта

Каждый факт хранит: `category`, `kind`, `value`, `subject`, `attributes` (до 8 строк в карточке),
`sourceIds`, `urls` (ссылки-доказательства), `firstSeen`, `confidence`
(`Подтверждено` / `Вероятно` / `Требует проверки`). Агрегатор (`report-core`) дедуплицирует факты,
строит связи «субъект → значение» и матрицу совпадений; отчёт выгружается в PDF, XLSX, JSON и HTML.

Итоговый документ содержит блоки: объект и исходные данные; личность; контакты; транспорт;
социальные сети; документы; онлайн-следы; недвижимость; юрлица; связи между объектами; источники и
методологию с ограничениями.
