# JB OSINT

Android-приложение для сбора и структурирования открытых данных (OSINT) по одному запросу: e-mail, телефон, домен, IP, никнейм или ФИО. Результат — единый отчёт, который можно выгрузить в PDF, Excel (XLSX) и JSON.

Приложение не показывает пользователю названия конкретных источников: в интерфейсе и в отчётах используется единый бренд **«Поиск JB OSINT»**.

## Возможности

- **Единый поиск.** Автоопределение типа запроса (e-mail, телефон, домен, IP, никнейм, ФИО) и параллельный опрос подключённых модулей с таймаутом.
- **Дедупликация и агрегация.** Факты нормализуются (телефоны, домены, e-mail), схлопываются дубликаты, строятся связи «субъект → значение» и матрица совпадений.
- **Оценка достоверности.** Каждый факт получает статус `CONFIRMED` / `PROBABLE` / `UNVERIFIED`, отчёт содержит раздел методологии и ограничений.
- **Свои модули.** Любой сервис с JSON-ответом подключается вручную: название, HTTPS-адрес с маркером `{query}`, способ передачи ключа (Bearer, свой заголовок, параметр адреса, JSON-тело `{"key": …}` или без ключа). Если способ не выбран — приложение само подбирает подключение: пробует GET и POST без тела и передачу ключа через `Authorization: Bearer`, `X-Api-Key` или параметр адреса, выбирая вариант, который вернул 2xx (рабочим считается и 401/403 — адрес и метод верны, ключ отклонён); в карточке на это время горит «Проверяется…», по успеху — «Модуль настроен успешно: GET, bearer». Сразу после сохранения выполняется тестовый запрос: ✅ «Модуль отвечает», ⚠️ «Ошибка 403: Forbidden» и т.п., 🚫 «Нет соединения»; при ошибке модуль автоматически отключается до устранения причины.
- **Быстрая настройка одним ключом.** Достаточно названия, API-ключа и ссылки на сервис (сайт или `@бот`): приложение читает страницу сервиса или описание бота, ищет документацию и само подбирает эндпоинт (`/search`, `/api/v1/search`, …), метод (GET → POST) и способ передачи ключа (`Bearer`, `X-Api-Key`, `?key=`/`?token=`, JSON-тело). Ответ 2xx фиксирует рабочую схему, 401/403 означает «адрес найден, ключ отклонён». Если подбор не удался — «Повторить автонастройку» (продолжает перебор) или «Ручная настройка» с уже подставленным наиболее вероятным шаблоном.
- **Правила разбора (field mapping).** Если ответ сервиса нестандартный, в карточке модуля задаются правила «JSON-путь → поле отчёта» (`data.username`, `data.items[].email`) с необязательной регуляркой для извлечения части значения. Без правил работает автоматический разбор по известным именам полей.
- **Единый формат фактов.** Значения приводятся к каноническим типам (почта, телефон, никнейм/профиль, полное имя, IP, домен, утечка) с нормализацией регистра, телефонов, доменов и URL — поэтому совпадения из разных модулей склеиваются и подтверждают друг друга.
- **Тестировать поиск.** На экране нового исследования есть предпросмотр: список найденных фактов без формирования отчёта и без сохранения в историю; показывает, сколько модулей ответило. Свой модуль работает в поиске наравне со встроенными, у него есть тумблер, проверка ключа и удаление. **Название сервиса остаётся только в приложении** — в PDF, Excel и JSON источник помечается нейтральным идентификатором `custom`, поэтому отчёт не раскрывает, к каким сервисам обращался аналитик.
- **Подробные факты без потери смысла.** Вместе с найденным значением сохраняются соседние поля ответа сервиса (страна, город, провайдер, источник утечки и т.п.): до 8 строк в карточке факта и полный набор в PDF (раздел «Детали исходного ответа»), Excel и JSON.
- **Диагностика модулей.** Кнопка «Диагностика» на экране ключей опрашивает все включённые модули и собирает отчёт: запрос (секреты замаскированы `***`), HTTP-код, время ответа, размер, структура JSON (пути к объектам и массивам), число разобранных фактов, поля правил, образец ответа и оценка («работает» / «0 фактов — задайте правила» / «код 403»). Отчёт копируется в буфер одной кнопкой и передаётся разработчику.
- **Интеллектуальный ассистент (Hugging Face).** Отдельная вкладка «Интеллектуальный ассистент» в настройках: API-ключ Hugging Face (`hf_…`), проверка ключа через `whoami`, выбор модели и пять сценариев.
  - **Аналитик** — связывает цифровые следы в связную картину, отделяет установленные факты от предположений.
  - **Исследователь** — сам формулирует 2–4 поисковых запроса, ищет их в публичной выдаче DuckDuckGo и делает выжимку найденного; в ответе перечислены ссылки на найденные страницы.
  - **Классификатор** — определяет тип значения (почта, телефон, никнейм, домен, IP, имя…) и релевантность; результат показывается меткой «ИИ: тип · релевантность» в карточке факта.
  - **Планировщик запросов** — до запуска модулей уточняет формулировку запроса.
  - **Синтезатор отчёта** — оформляет аналитическое резюме с заголовками и выводами; резюме попадает в PDF, Excel и JSON.
  - Сценарии включаются тумблерами и могут выполняться автоматически после поиска (типы, анализ, веб-исследование, резюме); всё можно запустить вручную кнопками на экране результатов.
  - Модели: `openai/gpt-oss-20b` (по умолчанию), `openai/gpt-oss-120b`, `meta-llama/Llama-3.1-8B-Instruct`, `meta-llama/Llama-3.3-70B-Instruct`, `Qwen/Qwen3.5-9B`, `deepseek-ai/DeepSeek-V3`; любой другой ID можно ввести вручную.
  - Запросы идут напрямую на `https://router.huggingface.co/v1/chat/completions` (HTTPS, Bearer-токен), ключ ассистента хранится в отдельном зашифрованном хранилище и передаётся только на Hugging Face. При редиректе на другой хост запрос прерывается, чтобы ключ не ушёл третьей стороне.
- **Управление API-ключами.** 20 источников, сгруппированных по темам; у каждого — тумблер включения, подсказка по формату ключа, ссылка на страницу выдачи и кнопка проверки валидности.
- **Шифрование ключей.** Ключи хранятся в `EncryptedSharedPreferences` (Android Keystore, AES-256-GCM), в UI показываются только маской.
- **Отчёты.**
  - PDF — 13+ страниц: титул, методология, сводная информация (профиль субъекта и общая картина), цифровые следы (граф связей и матрица пересечений), анализ утечек с оценкой риска и рекомендациями, Telegram-аналитика (каналы, аудитория, ссылки), реестр фактов с деталями ответов, оценка достоверности, ограничения, приложения A/B, колонтитулы. Шрифт Inter встроен в APK.
  - XLSX — до 8 листов (лист «ИИ-заключение» добавляется, когда ассистент подготовил выводы), стили, закреплённые заголовки, автофильтр.
  - JSON — схема `jb-osint/report/1.0` для интеграций; блок `ai_analysis` (`analysis`, `narrative`) появляется только при наличии текста ассистента.
- **Сохранение и отправка.** Файлы публикуются в общую папку `Documents/JB_OSINT_Reports` (Android 10+) либо во внешнее хранилище (Android 8–9) и открываются через системный Share Sheet.
- **Приватность.** `FLAG_SECURE` (скриншоты и превью в списке задач скрыты), HTTPS-only (`usesCleartextTraffic=false`), отключён автобэкап, история поиска хранится в зашифрованном виде с автоочисткой (7/30/90 дней или вручную).
- **Тёмная тема** с акцентами `#4F5BFF` / `#8B5CF6`, фон `#0B0E14`, шрифт Inter (Regular / SemiBold / Bold).

## Сборка

Требования: JDK 17, Android SDK (platform 35, build-tools 35.x), Gradle 8.11+.

```bash
export ANDROID_HOME=/path/to/android-sdk
echo "sdk.dir=$ANDROID_HOME" > local.properties

./gradlew :app:assembleDebug        # debug APK
./gradlew :app:assembleRelease      # подписанный release APK (R8 + shrink)
./gradlew test                      # unit-тесты (report-core + app)
```

Release-сборка ожидает keystore по пути из `app/build.gradle.kts` (`storeFile`) либо переменные окружения `JB_KEYSTORE`, `JB_KEYSTORE_PASSWORD`, `JB_KEY_ALIAS`, `JB_KEY_PASSWORD`.

## Структура

```
app/                       Android-приложение (Compose, minSdk 26, targetSdk 35)
  data/                    SecureStore, Net (OkHttp), Keys (каталог + валидаторы),
                           Storage (настройки/история), Search (детектор + коннекторы),
                           Assistant (роли, промты, разбор ответов, клиент Hugging Face,
                           поиск DuckDuckGo)
  report/ReportExporter.kt Экспорт PDF/XLSX/JSON, MediaStore, FileProvider
  ui/                      Theme, Components, AppViewModel, экраны, AppRoot
report-core/               Чистый Kotlin/JVM: модель, агрегатор, PDF-движок, XLSX, JSON
  pdf/TtfFont.kt           Парсер TrueType (встраивание CIDFontType2 + ToUnicode)
  pdf/PdfWriter.kt         Минимальный PDF-писатель (текст, фигуры, прозрачность)
```

`report-core` не зависит от Android и покрыт unit-тестами: агрегатор (дедупликация, нормализация, связи) и экспортёры (валидность PDF, XLSX, JSON).

## Источники (модули)

Дополнительно можно добавить собственные модули (см. выше) — количество не ограничено, каждый хранится в зашифрованном виде.

Поиск: Google CSE (ключ + CX), Яндекс XML (ключ + folderid), Brave Search, SerpAPI, DuckDuckGo и Wikipedia — последние два без ключа.

Инфраструктура: VirusTotal, Shodan, urlscan.io (без ключа), SecurityTrails (поддомены), IPinfo, RDAP (без ключа). Почта и телефоны: Hunter, Numverify, AbuseIPDB (репутация IP), Have I Been Pwned (утечки). Соцсети: GitHub, GitLab (без ключа), VK, Telegram через TGStat. Реестры: OpenCorporates. Плюс демо-модуль для проверки интерфейса без ключей.

Модули без ключа включаются тумблером и проверяются кнопкой «Проверить» — ключ для них не запрашивается. Для остальных ссылка «Где взять ключ» ведёт на актуальную страницу выдачи токена.

## Интеллектуальный ассистент

Ассистент — необязательный слой поверх поиска: он не ходит в платные источники и не подменяет факты, а работает с уже собранными данными.

1. Настройки → «Интеллектуальный ассистент» → вставьте ключ Hugging Face (страница выдачи открывается по ссылке из приложения) → «Сохранить».
2. «Проверить» обращается к `https://huggingface.co/api/whoami-v2`: код 200 — ключ активен, 401/403 — отклонён, нет сети — «Нет связи».
3. Выберите модель или введите ID вручную и включите нужные сценарии.
4. На экране результатов доступны кнопки «Проанализировать», «Интернет-поиск», «Оформить резюме»; выводы сохраняются в истории и попадают в отчёты.

Ошибки сервиса переводятся в понятный текст: «Hugging Face не принял ключ (код 401)», «Модель не найдена — проверьте ID», «Слишком много запросов, попробуйте позже». Если ключ не задан, ассистент молчит и поиск работает как обычно.

## Безопасность

- Ключи и история — только в зашифрованном хранилище; открытый текст в логах не появляется.
- Сетевые запросы идут по HTTPS, сертификаты проверяются системным trust store; ключи передаются в заголовках/параметрах и не логируются.
- Экспортированные файлы создаются в приватном кэше и передаются получателю через `FileProvider` с временным grant.
- В отчётах нет названий источников — только «Поиск JB OSINT».

## Ограничения

- Модули, требующие платных ключей, без ключа пропускаются; демо-режим возвращает синтетические данные для проверки интерфейса и экспорта.
- Приложение не обходит авторизацию, капчи и закрытые разделы: собираются только открытые данные, доступные по официальным API.
