# Настройка JB OSINT на телефоне

Краткая инструкция по тем трём сценариям, которые чаще всего «не работают» из-за отсутствия ключей или разрешений. Все шаги выполняются в самом приложении и в Termux; сборка APK описана в корневом `README.md`.

## 1. Вкладка «Утечки»

Источник утечки показывается всегда: сервис/файл, дата, состав данных и ссылка-доказательство (кнопка «Открыть источник»).

- Онлайн-источники (Have I Been Pwned, LeakCheck, Hudson Rock, Dyxless) возвращают **только метаданные**: название набора, дату и типы полей. Пароли они не отдают — это их API, а не баг приложения.
- Пароль берётся **только из локального индекса дампов**. Запустите «Глубокий поиск по дампам» на вкладке утечек и импортируйте файл дампа, который у вас уже есть. Форматы: `csv`, `tsv`, `txt`, `sql`, `json`, `log`, `lst`, `data`.
- Показ паролей включается плашкой «Пароли: вкл/выкл» прямо на вкладке или в **Настройки → Утечки → «Отображать пароли открыто»**. По умолчанию включено. При выключении пароль маскируется и не попадает в экспорт; при включении — попадает в PDF/XLSX/JSON/HTML.

Используйте эти данные только для своих учётных записей или по письменному согласию владельца.

## 2. Поиск по фотографии

Откройте **Ключи** и настройте два источника:

1. **SauceNAO (поиск по фото)** — бесплатный `api_key` с `saucenao.com/user.php?page=search-api`. Даёт обратный поиск по самому изображению: источник, автор, похожие страницы.
2. **Поиск по лицу (ProFaceFinder)** — два поля: API-ключ и **URL API (https)** конкретного эндпоинта, принимающего multipart-загрузку. Публичной документации у сервиса нет, поэтому адрес задаётся вручную. Проверка ключа просто проверяет доступность адреса; реальный ключ подтверждается первым поиском.

После этого на главном экране нажмите «Поиск по фотографии». Найденные страницы превращаются в факты: платформа, схожесть, статус, никнейм из ссылки и ссылка-доказательство. Ники можно передать агенту кнопкой «Передать @ник агенту».

Без ключей приложение честно показывает только SHA-256, dHash, EXIF, число лиц и ссылки для **ручной** проверки (Яндекс.Картинки, Google Lens, Bing, TinEye, IQDB) — это не выдаётся за найденное совпадение.

Совпадение изображения или лица не является доказательством тождества личности: статус «Требует проверки» означает, что нужна ручная сверка профиля.

## 3. GitHub-лаборатория и репозиторий как модуль поиска

1. Откройте вкладку **GitHub** и включите встроенную лабораторию — сервер работает внутри приложения на `127.0.0.1:8081`, Termux не нужен.
2. Вставьте ссылку вида `https://github.com/owner/repo`, при необходимости ветку/тег, нажмите «Загрузить и просканировать». Код репозитория при этом **не запускается** — только скачивается архив и проверяется тип проекта.
3. Нажмите «Найти шаблон модуля». Лаборатория **только читает** документацию и конфиги (`README*`, `*.md`, `*.json`, `*.yaml`, `*.yml`, `*.txt`, `*.py`, `*.js`, `*.ts`) и ищет HTTPS-адреса с маркером `{query}`.
4. Для найденного адреса нажмите «Настроить» — откроется редактор модуля в разделе «Ключи» с уже подставленным URL. Остаётся задать название, способ передачи ключа (Bearer, свой заголовок, параметр, JSON-тело или без ключа) и сам ключ, затем сохранить. Дальше модуль участвует в обычном поиске наравне со встроенными, а в отчёте указывается источник и ссылка-доказательство.

Если шаблонов не найдено, создайте модуль вручную: **Ключи → Свой модуль**, URL обязан содержать `{query}` и начинаться с `https://`.

## 4. Развёрнутый отчёт

Экспорт доступен кнопкой «Поделиться»: PDF, XLSX, JSON и автономный HTML. В PDF/XLSX есть разделы методологии, включая ограничения источников: онлайн-API утечек не отдают пароли, а совпадение по фото не доказывает личность. В HTML добавлены колонка «Источник» у каждого факта и блок «Методология и ограничения».

Файлы сохраняются в `Documents/JB_OSINT_Reports` (Android 10+) или во внешнем хранилище на старых версиях.
